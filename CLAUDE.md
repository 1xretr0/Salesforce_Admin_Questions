## Project Overview

This is a **multi-exam Salesforce Certification Simulator** — a standalone web application currently covering two certifications:
- **Platform Administrator (PLAT-ADMN-201)** — 150 practice questions, 7 category sections
- **Platform App Builder** — 351 practice questions, 5 category sections

An "Exam" dropdown in the header switches between them. Each exam provides two modes:
- **Study Mode**: Answer questions from the entire question bank, with immediate feedback and explanations
- **Exam Mode**: Timed simulation using a weighted 60-question sample drawn from the whole bank, with results shown at the end

The application is a pure client-side implementation with no backend or build process required.

## File Structure

- **[index.html](index.html)** — Single-page application shell: header (brand, exam switcher, score matrix, timer, mode toggle), dynamically-generated tab navigation/content, results modal
- **[app.js](app.js)** — All application logic (shared engine for every exam):
  - `EXAMS` registry: one config object per exam (question data, categories, tab layout, timer/passing-score/exam-count)
  - `activeExam`: the currently selected exam config; all rendering/scoring reads from it
  - State management: `state` object tracks answers, mode, timer, scoring, and the sampled exam-mode question set
  - Rendering: functions to generate the exam switcher, dashboard, tab nav + tab panes, question cards
  - Event handlers: exam switching, answer selection, submission, mode toggle, exam submission
- **[data/admin-questions.js](data/admin-questions.js)** — `ADMIN_CATEGORIES` + `ADMIN_QUESTIONS` (150 questions), extracted verbatim from the original `app.js`
- **[data/appbuilder-questions.js](data/appbuilder-questions.js)** — `APPBUILDER_CATEGORIES`, `APPBUILDER_SECTIONS`, `APPBUILDER_QUESTIONS` (351 questions), generated by `scripts/parse_appbuilder.py`
- **[scripts/parse_appbuilder.py](scripts/parse_appbuilder.py)** — one-off ETL script that parses `app_builder_practice_questions.md` into `data/appbuilder-questions.js`. Not part of the runtime app; re-run manually (`python3 scripts/parse_appbuilder.py`) only if the source markdown changes
- **[styles.css](styles.css)** — Complete styling with Salesforce-inspired design tokens, including the exam-switcher control
- **[Plat-Admn-201.md](Plat-Admn-201.md)** — Source markdown for the Admin 201 questions (reference only, not parsed at runtime)
- **[app_builder_practice_questions.md](app_builder_practice_questions.md)** — Source markdown for the App Builder questions, converted from the official PDF (reference only, not parsed at runtime — the generated `data/appbuilder-questions.js` is what the app loads)

## Key Data Structures

### Question Object Format
Identical schema across both exams; question `id`s are unique **within** an exam, not globally.
```javascript
{
  id: Number,              // Unique question ID within this exam's bank
  category: String,        // One of that exam's *_CATEGORIES constants
  text: String,             // Question text
  options: [                // Answer choices
    {letter: "A", text: "..."},
    {letter: "B", text: "..."},
    // ... up to E for some App Builder questions
  ],
  answer: ["A"],           // Correct answer(s) as array
  multi: Boolean,           // true for multiple-choice (2-3 answer) questions
  explanation: String       // Detailed explanation of correct answer
}
```

### EXAMS Registry (in app.js)
```javascript
const EXAMS = {
  admin: {
    id: "admin",
    questions: ADMIN_QUESTIONS,
    categories: ADMIN_CATEGORIES,
    tabs: [ { key, label, weight, desc, icon }, ... ],  // 7 category tabs + Full Exam
    examCount: 60,
    timerMinutes: 105,
    passingScore: 68,
    // ...plus display fields (fullName, subtitle, etc.)
  },
  appbuilder: {
    id: "appbuilder",
    questions: APPBUILDER_QUESTIONS,
    categories: APPBUILDER_CATEGORIES,
    tabs: [ ... 5 category tabs + Full Exam ... ],
    examCount: 60,
    timerMinutes: 105,
    passingScore: 63,
  },
};
let activeExam = EXAMS.admin;   // changed by the header exam switcher
```
Adding a future exam means adding one more `data/<exam>-questions.js` file plus one more entry here — the rendering/scoring engine below is entirely generic over `activeExam`.

### State Object
```javascript
state = {
  mode: "study"|"exam",       // Current mode
  currentTab: Number,          // Active tab index (0 = dashboard, last = Full Exam)
  answers: {                   // User answers keyed by question ID
    [qid]: ["A", "B"]
  },
  submitted: Set,               // Question IDs that have been submitted
  shuffledQuestions: {},        // Shuffled order per tab
  examQuestions: null,          // The weighted 60-question sample used while in Exam Mode
  timerInterval: null,          // Interval ID for exam timer
  timeRemaining: Number,        // Seconds remaining in exam mode
}
```
There is no password gate and no `localStorage` persistence — progress is in-memory only and resets on page reload or on switching exams.

## Core Functions

### Exam Switching
- `renderExamSwitcher()` — populates the `#exam-select` dropdown from `Object.values(EXAMS)`
- `switchExam(examId)` — resets state/timer, sets `activeExam`, updates header text, re-renders everything, resets to tab 0

### Rendering Pipeline
- `renderTabButtons()` — builds tab nav **and** the `.tab-pane` DOM nodes from `activeExam.tabs` (pane count varies per exam)
- `renderDashboard()` — builds the dashboard tab from `activeExam` (name, section weights, question count, timer, passing score)
- `renderAllQuizTabs()` — generates all category tabs plus the Full Exam tab; in Exam Mode the Full Exam tab uses the sampled set
- `renderQuizTab(tabIndex, title, questions)` — renders a single tab with its questions
- `renderQuestionCard(q)` — creates individual question card HTML
- `$active(selector)` — pane-scoped query helper (`.tab-pane.active <selector>`), used instead of a bare global `document.querySelector` wherever the same question id could exist in two panes at once (a category tab and the Full Exam tab), to avoid mutating a hidden duplicate node

### Answer Flow
1. `selectOption(qid, letter, isMulti)` — toggles answer selection (looks up the question in `activeExam.questions`)
2. `submitAnswer(qid)` — validates and locks in answer
3. `updateScoreMatrix()` — recalculates progress/score against `currentTotal()` and `activeExam.passingScore`
4. `updateTabProgress()` — updates per-tab completion indicators, bounded by `lastTabIndex()`

### Mode Management
- `toggleMode(isExam)` — switches between study/exam modes
  - Study: full question bank, immediate feedback, explanations visible after submit
  - Exam: calls `sampleExamQuestions()` for a fresh weighted sample, starts the timer, jumps to the Full Exam tab
- `sampleExamQuestions(exam)` — builds the `examCount`-question weighted sample: proportionally allocates counts per category via the largest-remainder method (so the total sums exactly to `examCount`), randomly draws that many questions per category, backfills from leftover questions if any category pool falls short, then shuffles the combined set
- `startTimer()` / `stopTimer()` — manage the countdown, duration = `activeExam.timerMinutes * 60`
- `submitExam()` — ends exam, scores against the sampled set (`currentQuestionSet()`), calculates per-section results, shows the results modal

### Exam Results
- `showResultsModal(answered, correct, score, passed, sections, total)` — displays final results with:
  - Overall score out of `total` (pass threshold = `activeExam.passingScore`)
  - Per-section breakdown
  - Animated circular progress indicator
- `closeResults()` — reveals all answers with correct/incorrect styling, scoped to `currentQuestionSet()`

## Development Workflow

### Running the Application
Simply open [index.html](index.html) in a browser:
```bash
open index.html
```
Or use a local server:
```bash
python3 -m http.server 8000
# Then navigate to http://localhost:8000
```

There is no password gate — the app loads directly into Study Mode on the Admin exam.

### Making Changes

**To modify or add questions:**
1. Admin: edit `ADMIN_QUESTIONS` in [data/admin-questions.js](data/admin-questions.js)
2. App Builder: edit `APPBUILDER_QUESTIONS` in [data/appbuilder-questions.js](data/appbuilder-questions.js), or re-run `scripts/parse_appbuilder.py` after editing the source markdown
3. Each question must follow the schema above; `answer.length` must match `multi` (single = 1 letter, multi = 2+ letters)
4. Refresh browser to see changes

**To add a new exam:**
1. Create `data/<exam>-questions.js` exporting `<EXAM>_CATEGORIES` and `<EXAM>_QUESTIONS`
2. Add a script tag for it in [index.html](index.html), before `app.js`
3. Add a new entry to the `EXAMS` registry in [app.js](app.js) with its `tabs`, `examCount`, `timerMinutes`, and `passingScore`
4. No other engine code needs to change — rendering/scoring is generic over `activeExam`

**To adjust styling:**
1. Edit design tokens in [styles.css](styles.css)
2. Modify component styles in their respective sections
3. The design system uses CSS custom properties for consistency

**To change exam parameters:**
1. Timer duration: edit `timerMinutes` on the relevant exam in the `EXAMS` registry in [app.js](app.js)
2. Passing score: edit `passingScore` on the relevant exam (Admin: 68, App Builder: 63)
3. Exam-mode sample size: edit `examCount` on the relevant exam (currently 60 for both)

### No Build Process
This is intentional — the project is deployment-ready as static files. No npm, webpack, or transpilation required.

## State Management Pattern

The app uses a simple global `state` object with **no persistence** — there is no `localStorage` usage anywhere in the codebase. Answers, submissions, and timer progress are held only in memory and are lost on page refresh or when switching exams via the header dropdown.

No framework (React, Vue, etc.) is used — this is vanilla JavaScript with direct DOM manipulation.

## Testing Locally

There are no automated tests beyond `node --check` syntax validation on the JS files. Manual testing workflow:
1. Open in browser (or serve via `python3 -m http.server`)
2. Test both exams via the header dropdown (Admin 201, Platform App Builder)
3. Test both modes per exam:
   - Study: Submit answers, verify explanations appear, check scoring
   - Exam: Start timer, confirm a 60-question weighted sample loads, answer questions, submit exam, review results modal (score out of 60, pass threshold per exam)
4. Test tab shuffling with "Shuffle Questions" button
5. Confirm switching exams mid-session resets state cleanly and re-renders the correct tab set
